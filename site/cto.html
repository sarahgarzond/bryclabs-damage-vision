Compare the classifier approaches


Start with a baseline and run each change on the same frozen cases. The options below are an experiment plan.




Hosted vision API
Use a backend-held key and structured image input. Check billing, photo handling, latency and cost.


Self-hosted Qwen-VL
Use the repo GPU backend with the same schema. Record the model, device and memory.


Detector + vision model
Use component boxes to guide damage classification. Keep the full-image pass to recover regions the detector misses.


Evidence rules
Require visible separation before calling a grout line a crack. Keep unsupported attributes unknown.


Selective crop review
Recheck a difficult region at native resolution, preserve context and map evidence back to original pixels.


Example-guided classification
Show labelled development examples of cracks, intact grout and ambiguous lines. Test with and without examples.


Multi-photo classification
Use context and close-up views from the same case. Attach a photo ID to each supporting observation.


Supervised specialist
Train a small classifier on frozen embeddings for a narrow confusion pair using separate development labels.


Two-model cross-check
Have a second vision model review a disputed observation. Measure disagreements, withheld findings and added cost.

Judging rubric


Each criterion links the visible demo to the evidence needed in a scored run.




30%
Extraction quality
Use the demo regions to inspect damage type, component, material, location and visible traits. Score finding precision, recall and F1, per-field accuracy, and box IoU on annotated images.


30%
Evaluation approach
Freeze a case-grouped gold set. Target 60 clear, 25 ambiguous and 15 negative images, including 20 blind double-labelled images. Record agreement and adjudication. Compare the baseline, taxonomy, and one targeted improvement. Report per-label support and failures.


20%
Uncertainty & robustness
Open the dark-corner and negative cases. Track unsupported findings and false positives together with recall. Repeat runs and test blur, darkening and crops. Check whether the system withholds claims when evidence disappears.


10%
Reproducibility
Use the repo setup, JSON schemas, exact run commands and pinned model settings. Save outputs for supplied images and log corrupt inputs or model errors.
Open setup instructions · Open JSON schemas


10%
Efficiency
Report median and p95 end-to-end latency, model calls per photo, and API cost or peak GPU memory. Record device, input resolution and batch size alongside scores.

24-hour handoff


  1. Schema owner · Hours 0–3. Agree on IDs, evidence fields and policy-critical unknowns.
  2. Model owner · Hours 0–13. Run the baseline, extend the vocabulary, and test one targeted classifier change.
  3. Evaluation owner · Hours 0–19. Coordinate labelling, freeze the case split and score real predictions.
  4. Integration owner · Hours 13–24. Reproduce the run, save JSON, record resources and rehearse the walkthrough.
